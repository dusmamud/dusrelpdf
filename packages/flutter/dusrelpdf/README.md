# dusrelpdf — Dart/Flutter bindings for dusrelpdf

Idiomatic Dart bindings (dart:ffi) over the dusrelpdf Rust core, via
the C ABI in `crates/dusrelpdf-ffi`. All PDF logic lives in Rust; this
package only converts Dart values to native buffers / JSON options and
back. **Not published to pub.dev.**

## Build the native library first

```sh
# from the repo root
cargo build -p dusrelpdf-ffi --release
# Linux:   target/release/libdusrelpdf.so
# macOS:   target/release/libdusrelpdf.dylib
# Windows: target/release/dusrelpdf.dll
```

The Dart code loads that file (see "Finding the library" below).
Without it, constructing `Dusrelpdf()` throws an
`ArgumentError` from `DynamicLibrary.open`.

## Use it

```dart
import 'package:dusrelpdf/dusrelpdf.dart';

final pdf = Dusrelpdf();

// Merge two PDFs; null options = Rust defaults.
final merged = pdf.merge([a, b]);

// Summary without modifying the PDF.
final info = pdf.getPdfInfo(merged);
print(info.pageCount); // e.g. 8

// Rotate page 1 by 90 degrees.
final rotated = pdf.rotate(doc, options: {'angle': 90, 'pages': [1]});

// Errors are DusrelException with a stable code:
try {
  pdf.extractPagesRange(doc, '9');
} on DusrelException catch (e) {
  print(e.code); // INVALID_RANGE
  print(e.messageEn);
  print(e.messageHi);
}
```

## Finding the library

`Dusrelpdf({String? libraryPath})` resolves the native library as:

1. The explicit `libraryPath` argument.
2. The `DUSRELPDFFI_LIB` environment variable.
3. Repo-layout candidates relative to the current working directory
   (`../../../target/release/libdusrelpdf.{so,dylib,dll}` and nearer
   variants) — this is what `dart test` uses.
4. The bare library name on the system search path.

## API

| Method | Notes |
| --- | --- |
| `version` | library version string |
| `merge(List<Uint8List>, {options})` | `Uint8List` out |
| `split(Uint8List, List<List<int>>, {options})` | one output per range |
| `splitRanges(Uint8List, "1-3,4-5", {options})` | one output per chunk |
| `splitEachPage(Uint8List, {options})` | one output per page |
| `extractPages(Uint8List, List<int>, {options})` | |
| `extractPagesRange(Uint8List, "1-3,5", {options})` | |
| `removePages(Uint8List, List<int>, {options})` | |
| `reorderPages(Uint8List, List<int>, {options})` | every page exactly once |
| `rotate(Uint8List, {options})` | `{'angle': 90}` — must be a multiple of 90 |
| `getPdfInfo(Uint8List, {options})` | `PdfInfo` |
| `imagesToPdf(List<Uint8List>, {options})` | PNG/JPEG in |
| `addWatermark(Uint8List, {image, options})` | image null = text watermark |
| `addPageNumbers(Uint8List, {options})` | format must contain `{n}` |
| `placeSignature(Uint8List, Uint8List image, {options})` | image placement, not a digital signature |
| `bulkExtract(Uint8List, List<List<int>>, {options})` | `List<BulkItem>`; one bad selection fails only its item |

All methods are synchronous and throw `DusrelException` on failure,
carrying the stable dusrelpdf code (`INVALID_PDF`, `ENCRYPTED_PDF`,
`PAGE_OUT_OF_RANGE`, `EMPTY_INPUT`, `INVALID_RANGE`, `INVALID_ANGLE`,
`INVALID_IMAGE`, `INVALID_ARGUMENT`, `OPERATION_FAILED`) plus English
and Hindi messages.

**Options:** a partial `Map<String, dynamic>` with the same
snake_case keys as the Rust core options
(`crates/dusrelpdf/src/options.rs`). Missing keys keep the Rust
defaults; pass `null` for all defaults. `page_size` also accepts
`{'width': w, 'height': h}` or `[w, h]` for a custom size.

## Tests

```sh
dart test        # 17 tests, real fixture PDFs in test/testdata/
dart analyze     # 0 issues
dart format lib test --output=none --set-exit-if-changed
```

Fixtures (`test/testdata/three.pdf`, `test/testdata/five.pdf`) were
generated by the repo's own CLI:

```sh
cargo run -p dusrelpdf-cli -- mock --pages 3 -o packages/flutter/dusrelpdf/test/testdata/three.pdf
cargo run -p dusrelpdf-cli -- mock --pages 5 -o packages/flutter/dusrelpdf/test/testdata/five.pdf
```

The 1×1 PNG used by the image tests is embedded in the test file
(base64), so no binary image fixture is committed.

**What was NOT tested here:** the flutter CLI is not installed on
this machine, so no widget-level testing was run. Only dart:ffi
loading + operations were tested (`dart test`). This package uses no
Flutter imports and works from pure Dart; a Flutter app can depend
on it, but see the next section.

## Bundling the native library in a Flutter app

This package ships the Dart FFI layer only — it does **not** include
the Flutter plugin scaffolding (android/ios/macos/windows runner
registration) that copies `libdusrelpdf.{so,dylib,dll}` into the app
bundle. Until that scaffolding exists, a Flutter app must bundle the
library itself (e.g. copy the built `.so`/`.dylib`/`.dll` into the
platform's native-library directory and pass its path to
`Dusrelpdf(libraryPath: ...)`), or load it from an absolute path.
On Linux desktop, placing `libdusrelpdf.so` next to the app binary
and passing that path works.

## Honest limits

- Same v0.1.0 core limits: no rendering, no tolerant repair, merge
  drops original outlines (rebuilt flat), watermark / page-number
  text is ASCII only, signature is a raster image.
- Whole documents live in memory; no streaming.
- `.dylib` / `.dll` builds were not produced on this Linux VM — the
  code paths are identical (same cdylib, same header), but macOS /
  Windows loading is untested here.
- No pub.dev publish (deliberate: this piece does not publish).
