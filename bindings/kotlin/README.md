# dusrelpdf — Kotlin / Android package

Android library (AAR) wrapping the UniFFI-generated Kotlin bindings for
[dusrelpdf](https://github.com/dusmamud/dusrelpdf) — offline PDF toolkit
(merge, split, extract, remove, reorder, rotate, images-to-PDF, watermark,
page numbers, signature-image placement).

**Maven coordinates:** `io.github.dusmamud:dusrelpdf:0.1.0`

## Layout

```
bindings/kotlin/
├── settings.gradle.kts                  # root project "dusrelpdf", module :dusrelpdf
├── build.gradle.kts                     # plugin versions (AGP 8.5.2, Kotlin 2.0.20)
├── gradle.properties
├── gradlew / gradlew.bat                # Gradle 8.7 wrapper (run from this directory)
├── gradle/wrapper/gradle-wrapper.properties
├── uniffi/dusrelpdf_uniffi/
│   └── dusrelpdf_uniffi.kt              # GENERATED by UniFFI 0.28.3 — DO NOT EDIT
│                                        # (single source of truth; the module
│                                        # compiles it in place, never copies it)
└── dusrelpdf/                           # the Android library module
    ├── build.gradle.kts                 # com.android.library + maven-publish
    ├── consumer-rules.pro
    └── src/main/
        ├── AndroidManifest.xml
        └── jniLibs/<abi>/libdusrelpdf_uniffi.so   # built, NOT committed (see below)
```

## Usage (once published)

```kotlin
// settings: mavenCentral()
// build.gradle.kts:
dependencies {
    implementation("io.github.dusmamud:dusrelpdf:0.1.0")
}
```

```kotlin
import uniffi.dusrelpdf_uniffi.*

val merged = mergePdfs(listOf(pdfA, pdfB), MergeOptions())
println(getPdfInfo(merged, CommonOptions()).pageCount)  // 5

val rotated = rotatePages(pdf, RotateOptions(angle = 90))

try {
    extractPages(pdf, listOf(9u), PageSetOptions())
} catch (e: DusrelException.PageOutOfRange) {
    println(e.code)      // PAGE_OUT_OF_RANGE
    println(e.reasonEn)  // Page 9 is out of range ...
    println(e.reasonHi)  // Page 9 range se bahar hai ...
}
```

See `crates/dusrelpdf-uniffi/README.md` for the full API table (16
functions, records, enums, error codes in EN + HI).

## Building

Requirements: **JDK 17** and an **Android SDK** (API 34, build-tools
34.0.0). `ANDROID_HOME` (or `sdk.dir` in `local.properties`) must point
at the SDK.

```sh
cd bindings/kotlin
./gradlew :dusrelpdf:assembleDebug     # compile Kotlin + build debug AAR
./gradlew :dusrelpdf:assembleRelease   # release AAR (needs the .so files, below)
./gradlew :dusrelpdf:publishToMavenLocal   # local smoke test of the POM + AAR
```

### The native library (`.so` files) — built, not committed

The generated Kotlin code loads `libdusrelpdf_uniffi.so` through JNA at
first use. The `.so` files are build artifacts and are **intentionally
not committed** (the repo root `.gitignore` ignores `*.so`). Build them
with [cargo-ndk](https://github.com/bbqsrc/cargo-ndk) — one `.so` per
Android ABI — and copy them into `src/main/jniLibs/`:

```sh
# From the repo root. Requires the Android NDK (ANDROID_NDK_HOME) and:
cargo install cargo-ndk
rustup target add aarch64-linux-android armv7-linux-androideabi \
                 i686-linux-android x86_64-linux-android

cargo ndk -t arm64-v8a -t armeabi-v7a -t x86 -t x86_64 \
    -o bindings/kotlin/dusrelpdf/src/main/jniLibs \
    build -p dusrelpdf-uniffi --release
```

This produces:

```
src/main/jniLibs/
├── arm64-v8a/libdusrelpdf_uniffi.so
├── armeabi-v7a/libdusrelpdf_uniffi.so
├── x86/libdusrelpdf_uniffi.so
└── x86_64/libdusrelpdf_uniffi.so
```

Gradle packages whatever is in `src/main/jniLibs/` into the AAR.
Compiling the Kotlin code (`assembleDebug`) does **not** need the `.so`
files — only packaging a release AAR and running on a device do.

## Publishing to Maven Central (later — NOT done yet)

The module is wired for publication (`maven-publish`, POM metadata:
MIT licence, developer `dusmamud`, SCM
`https://github.com/dusmamud/dusrelpdf`) but **nothing is published**.
The release steps, when the time comes:

1. Build the `.so` files per ABI (above) and `assembleRelease`.
2. Sonatype Central: namespace `io.github.dusmamud` (GitHub-verified),
   a Central portal token, and GPG signing of the AAR + POM
   (the `signing` plugin is deliberately not applied here — no secrets
   in this repo).
3. Publish the release AAR (`io.github.dusmamud:dusrelpdf:0.1.0`) to
   Central; verify it resolves from `mavenCentral()` in a clean project.

## Maintenance notes

- **Regenerating bindings:** run `scripts/regenerate-uniffi.sh` from the
  repo root. It regenerates `uniffi/` only — do not hand-edit the
  generated file. The module compiles it in place via a `java.srcDirs`
  entry (`../uniffi`); if a future AGP version ever rejects a source dir
  outside the module, the fallback is a `Copy` task into
  `build/generated/source/uniffi` wired before `compileDebugKotlin`.
- **Regeneration script caveat (integration note):** the current
  `scripts/regenerate-uniffi.sh` does `rm -rf bindings/kotlin` and diffs
  the whole directory, which would delete this Gradle project and fail
  its `--check`. Before the next regeneration it must be updated to
  regenerate/diff only `bindings/kotlin/uniffi/`.

## Dependencies

| Dependency | Why |
| --- | --- |
| `net.java.dev.jna:jna:5.14.0@aar` (`api`) | FFI runtime for the generated bindings (UniFFI Kotlin needs JNA ≥ 5.12.0). `api` so consumers get it transitively — without it, first use crashes with `NoClassDefFoundError`. `@aar` is the Android packaging. |
| AGP 8.5.2 / Kotlin 2.0.20 / Gradle 8.7 | Pinned, known-good combination; AGP 8.5.x needs Gradle ≥ 8.7 and JDK 17. |

## Honest limits

Same as the core (see `crates/dusrelpdf-uniffi/README.md`): no PDF
rendering, no tolerant repair of malformed PDFs, watermark / page-number
text is ASCII only, signature placement is a raster image — not a
cryptographic digital signature.
