# dusrelpdf website

Public website for **dusrelpdf** — the offline PDF toolkit (merge, split,
extract, remove, reorder, rotate, images-to-PDF, watermark, page numbers,
signature-image placement). Built with [Astro](https://astro.build) +
[Starlight](https://starlight.astro.build). Fully static: no SSR, no backend,
no database.

Not deployed yet — the `site` URL in `astro.config.mjs` is a placeholder
until the site is put on Cloudflare Pages (like indycheck).

## Run it

```bash
npm install
npm run dev      # local dev server at http://localhost:4321
npm run build    # production build into ./dist/ (builds the WASM playground first)
npm run preview  # preview the production build locally
```

Requires Node 18+ and `wasm-pack` (for the playground WASM build — see below).

## What's here

| Path | What it is |
| --- | --- |
| `src/pages/index.astro` | Landing page — hero, install commands, 10-feature table, honest limits |
| `src/pages/playground.astro` | In-browser playground — pick a local PDF, run merge / extract / rotate / watermark / page numbers / split, download the result. Files never leave the browser. |
| `src/content/docs/` | Starlight docs: installation, quickstart, options, error codes, one page per operation (10), info & bulk, CLI, Rust / JS / Python API, limitations, comparison, changelog |
| `src/lib/wasm-pkg/` | WASM build output (gitignored, regenerated by `npm run build`) |
| `public/wasm/` | Copy of the WASM build served to the playground (gitignored) |
| `public/favicon.svg`, `public/og.svg` | Favicon + social card |

## How the playground's WASM works

`npm run build` runs `prebuild` first (`scripts/build-wasm.mjs`), which runs
`wasm-pack build --target web crates/dusrelpdf-wasm` into
`src/lib/wasm-pkg/` and copies it to `public/wasm/`. The playground
lazy-loads `/wasm/dusrelpdf_wasm.js` on first use.

The build script **fails loudly** if `wasm-pack` is missing or the build
fails — the site must never ship a playground that silently does nothing.

## Docs

Docs are in English for v0.1; the error messages in the package itself are
bilingual (every error carries `reason_en` and `reason_hi` in Roman-script
Hinglish). Every doc page carries the honest-limits note: v0.1.0 has no PDF
rendering, no tolerant repair of malformed PDFs, merge drops the original
outline trees, and signature placement is an image, not a cryptographic
digital signature.
