Reorder the pages of a PDF. The new order must list **every page exactly
once** — a complete permutation, 1-based.

## Rust

```rust
use dusrelpdf::{reorder_pages, PageSetOptions};

let pdf = std::fs::read("report.pdf")?; // 3 pages
// Last page first:
let out = reorder_pages(&pdf, &[3, 1, 2], &PageSetOptions::default())?;
```

Signature: `reorder_pages(pdf: &[u8], order: &[u32], options: &PageSetOptions) -> Result<Vec<u8>>`.

## JavaScript

```js
import { reorderPages } from 'dusrelpdf';

const out = reorderPages(pdf, [3, 1, 2]);
```

## Python

```python
from dusrelpdf import reorder_pages

out = reorder_pages(pdf, [3, 1, 2])
```

## CLI

```bash
dusrelpdf reorder report.pdf --order "3,1,2" -o reordered.pdf
# Reordered to 3,1,2, wrote reordered.pdf
```

## The permutation rule

`order` must contain every page number from `1` to the page count, each
exactly once. Anything else is an error:

| Order (3-page PDF) | Result |
| --- | --- |
| `[3, 1, 2]` | OK — valid permutation |
| `[1, 2]` | `INVALID_ARGUMENT` — 2 entries for a 3-page PDF |
| `[1, 2, 2]` | `INVALID_ARGUMENT` — page 2 listed twice |
| `[1, 2, 4]` | `PAGE_OUT_OF_RANGE` — page 4 does not exist |
| `[0, 1, 2]` | `PAGE_OUT_OF_RANGE` — pages are 1-based |

This strictness is the point: a reorder that silently dropped a page would
lose content. If you want a subset in a new order, use
[Extract](/reference/extract/) instead — it allows any pages, in any order,
with duplicates.

## Errors

| Code | When |
| --- | --- |
| `INVALID_ARGUMENT` | Wrong number of entries, or a duplicated page. |
| `PAGE_OUT_OF_RANGE` | A page number is `0` or past the last page. |
| `INVALID_PDF` | The input is not a parseable PDF. |
| `ENCRYPTED_PDF` | The input is encrypted and no (or a wrong) password was given. |
